## Architecture findings

1. Initial SSR HTML is outside `withEdgeCache`/Cache API. Current edge caching covers public JSON endpoints, not the HTML response generated by the SSR page routes.
2. On an API cache miss, `withEdgeCache` resolves the catalog version before the handler. `runCatalogQuery` then reads the paginated projection and, when `includeTotal` is enabled, performs an exact count. Routes that opt out of totals avoid that count, but the total-bearing path still pays version + page + COUNT work.

These are evaluation findings, not implementation changes. They must be measured against agreed thresholds before progressive activation.
